# rel-broll-creator — מפעל הבירולים

## תפיסת על

בירול = קליפ קצר (2-6 שניות), אנכי, **מושתק**, של רגע אמיתי מהמועדון/אירוע, שמשתלב כ-overlay
בעריכות סושיאל. הסקיל הזה מייצר את הנכסים האלה מחומר גלם — בשני מצבים:

| מצב | קלט | פלט |
|---|---|---|
| **A — סרטון ארוך** | תדמית/קומפילציה/סרטון תחרות (דקות) | N בירולים נבחרים, חתוכים מהשוטים הטובים |
| **B — קטעים קצרים** | כמה קליפים קצרים מצולמים | כל קליפ → בירול (או צירוף קליפים → בירול אחד) |

**הלב של הסקיל:** הבחירה היא **ויזואלית ואנושית** — הכלי מאתר מועמדים ומפיק contact sheet,
ואתה (או הראל) בוחר את הטובים. אל תבחר עיוור; תמיד תסתכל על הפריימים.

---

## ברירות מחדל מותגיות (אושרו ע"י הראל 22.6.2026 — אל תשנה בלי בקשה)

- **אנכי 1080×1920** עם **blur-fill** — הרקע מטושטש למעלה/למטה, התוכן באמצע. **לא מאבד שום דבר מהפריים.** המקור לרוב אופקי (1920×1080), הריילס אנכיים — blur-fill פותר את זה נקי.
- **אודיו מושתק תמיד** (`-an`). בירול הוא overlay מושתק; באים בלי קול.
- **libx264 crf 20, veryfast, +faststart.** איכות יפה, קובץ קטן (~1-8MB לקליפ).
- **שם הקובץ חייב לכלול "בירול"** — ככה rel-social-video-editor מזהה אותו כ-B-roll. פורמט: `בירול {אירוע} - {NN} {תיאור}.mp4`.
- **מספור רציף** — באצ' שני ממשיך מאיפה שהראשון נגמר (15, 16, ...).

**מסגור — מתי לחרוג מ-blur-fill (`--mode`):**
- `blur` (ברירת מחדל) — שומר הכל. מומלץ לרוב, ובמיוחד לשוטים רחבים (קהל/קבוצה).
- `crop` — center-crop אנכי מלא-פריים. יותר punch על שוט אקשן עם נושא ממורכז, אבל חותך צדדים ומעלה רזולוציה. שקול לשוטי הרמה/חטיפה ממורכזים.
- `horizontal` — שומר מסגור מקורי (master גמיש, לא reel-ready). רק אם מבקשים.

## איפה שומרים

`{CONTENT_ROOT}/בירולים/{אירוע}/` — למשל `תוכן שיווקי/בירולים/Throwdown 2025/`.
`CONTENT_ROOT = /Users/hayon/Library/Mobile Documents/com~apple~CloudDocs/קרוספיט אריאל/01 - שיווק/תוכן שיווקי`.

**Descript:** הבית של ספריית הבירולים הוא ה-**Media Library** של Descript (תיקיית "בירולים") — משותף לכל הפרויקטים. הראל גורר לשם ידנית. **אל תיצור פרויקט Descript ייעודי לבירולים** (מיותר). לשימוש בעריכה ספציפית — rel-social-video-editor מייבא את הבירול הרלוונטי ישירות לפרויקט הסרטון.

## הכלים (`scripts/`)

| כלי | מה עושה |
|---|---|
| `broll_scan.py` | מצב A שלב 1: scene-detect + contact sheet + candidates.json |
| `broll_make.py` | יצירת הבירולים: `cut` (מסרטון+plan), `format` (קטעים→בירולים), `stitch` (צירוף→בירול) |
| `broll_sheet.py` | contact sheet של תוצרים — **לאימות ויזואלי** לפני "מוכן" |

ל-`--help` מלא: `python3 scripts/broll_make.py cut --help`.

## מצב A — סרטון ארוך → בירולים

### שלב 1 — סריקה
```
python3 scripts/broll_scan.py --video "{גלם}" --out "{OUTDIR}" --min-dur 2.0 [--exclude {זמנים שכבר השתמשת}]
```
- כתוב `OUTDIR` לתיקיית **outputs** (כדי שתוכל לקרוא את ה-contact sheet — מיפוי נתיב host).
- מחזיר: `contact_NN.jpg` + `candidates.json` (idx, start, end, dur) + רשימת `#N: start-end (dur)`.
- **לבאצ' "מחלקים אחרים"** (עוד בירולים מאותו סרטון): העבר ל-`--exclude` את ה-start-times שכבר חתכת, וה-scan ידלג עליהם.

### שלב 2 — בחירה ויזואלית (קריטי)
**קרא את ה-contact sheet** (Read על נתיב ה-host של ה-jpg). האריחים בסדר row-major = `#0, #1, ...`.
בחר ~12-15 שוטים **טובים ומגוונים**:
- ✅ אקשן (הרמות, חטיפות, קפיצות, ריג), אינטנסיביות (ריכוז/צ'וק), קהל/קהילה, ספורטאים מגוונים.
- ❌ דלג: לוגו/אאוטרו, שוטי מעבר מטושטשים, חשוכים מדי, וכפילויות-תוכן של מה שכבר בחרת.
- שאף ל**פיזור על פני הסרטון** ולגיוון תנועות.

### שלב 3 — חיתוך
בנה `plan.json` מהאינדקסים שבחרת (קח start/dur מ-candidates.json; הוסף `num` רץ ו-`desc` קצר):
```json
[{"num":15,"start":29.7,"dur":2.3,"desc":"הרמה מעל הראש"}, ...]
```
> טיפ: קצץ ~0.1ש מההתחלה ו-~0.2ש מהמשך כדי לא לתפוס פריימים של החתך (start+0.1, dur=dur-0.2).
```
python3 scripts/broll_make.py cut --video "{גלם}" --plan plan.json --dest "{CONTENT_ROOT}/בירולים/{אירוע}" --event "{אירוע}"
```

### שלב 4 — אימות (חובה)
```
python3 scripts/broll_sheet.py --dir "{DEST}" --out "{OUTDIR}/verify.jpg"
```
**קרא את verify.jpg** ואשר שהמסגור/האיכות תקינים. רק אז "מוכן".
> **תיאורים בשמות = best-guess.** הם נגזרים מהפריים האמצעי בזמן הסריקה ועלולים להחטיא (למשל "הרמה" שמתגלה כ"חתירה"). אחרי האימות הוויזואלי — אם תיאור גרוס שגוי, תקן את השם או דווח להראל. עדיף תיאור מעורפל-נכון מתיאור ספציפי-שגוי.

## מצב B — קטעים קצרים → בירולים

כשהראל מביא כמה קליפים קצרים (לא סרטון אחד ארוך):

**כל קליפ → בירול נפרד:**
```
python3 scripts/broll_make.py format --clips a.mov b.mov c.mov --dest "{DEST}" --event "{אירוע}" --start-num {N}
```

**צירוף כמה קטעים לבירול אחד (רצף):**
```
python3 scripts/broll_make.py stitch --clips a.mov b.mov --dest "{DEST}" --event "{אירוע}" --num {N} --desc "רצף"
```
תמיד אַמת עם `broll_sheet.py` אחרי.

## סביבת ריצה

- **סנדבוקס מועדף** (יש בו ffmpeg, וקבצים שהראל מעלה יושבים ב-uploads). מהיר ויציב.
  - חיתוך הרבה קליפים בקריאה אחת עלול לחרוג מ-45ש — פצל ל-batches של ~7, או חתוך ל-`/tmp` (מקומי-מהיר) ואז `cp` לתיקיית היעד ב-iCloud.
- **תיקיית היעד ב-iCloud** (`תוכן שיווקי/בירולים/...`) נגישה מהסנדבוקס: יצירה/העתקה עובדת, **מחיקה/שינוי-שם חסומים** — לזה צריך Desktop Commander (על נתיב ה-Mac).
- **קריאת contact sheets:** כתוב אותם ל-outputs; קרא בנתיב ה-host (לא `/sessions/...`). הסנדבוקס וה-Read רואים נתיבים שונים — Read רץ על ה-host.
- ffmpeg של Homebrew על ה-Mac חסר `drawtext` — אל תסמוך על תוויות צרובות; השתמש במיפוי position→index.

## אינטגרציה — איך הבירולים נכנסים לסרטונים

הסקיל הזה רק **מייצר** בירולים. ה*שילוב* שלהם בעריכת סרטון נעשה ב-**rel-social-video-editor**
(שלב B-roll): ייבוא הבירול הרלוונטי לפרויקט הסרטון + agent overlay מושתק בטיימקוד שתואם לנרטיב.
ב-Throwdown מותר B-roll גם בתוכן ערך (חריג מאושר). שיטת ההתאמה: בירול לרגע שהדיבור מתאר אותו.
